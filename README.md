# HVE Core for Claude Code

[HVE Core](https://github.com/microsoft/hve-core) is Microsoft's agentic software-delivery framework:
Research, Plan, Implement, Review (RPI), code review, security, privacy, accessibility, responsible AI,
project planning, design thinking and more. Microsoft ships it for GitHub Copilot. This repository
converts it into a Claude Code plugin so you can use the same workflows in Claude Code.

This is an unofficial conversion. It is not published or supported by Microsoft or Anthropic. HVE Core
is MIT-licensed; its license and third-party notices are in `plugins/hve-core/`. The converter
(`convert.py`) is MIT-licensed too; see [LICENSE](LICENSE).

## Install

You need Claude Code and read access to this repository.

```bash
claude plugin marketplace add ari20089/hve-core-claude-code
claude plugin install hve-core@hve-core-claude-code
```

Then open Claude Code in a project and run this once per project:

```text
/hve-core:setup
```

It copies HVE Core's coding standards and working-folder conventions into `.claude/rules/hve-core/`.
Claude Code asks you to approve the copy. Commit that folder to share the rules with everyone who
clones the project. Use `/hve-core:setup user` instead to install them for every project on your
machine. Don't skip this step: the RPI skills depend on these rules.

## Use

Skills run as `/hve-core:<name>`. Type `/hve-core:` to see the list. The core workflow:

```text
/hve-core:rpi-research topic=<short-name> Research <the task>
/hve-core:rpi-plan
/hve-core:rpi-implement
/hve-core:rpi-review
```

Other starting points:

- `/hve-core:git-commit`, `/hve-core:pull-request`, `/hve-core:code-review`
- `claude --agent hve-core:rpi-agent` runs the whole RPI lifecycle in one session
- `claude --agent hve-core:security-reviewer`, and 55 other agents listed in
  [plugins/hve-core/README.md](plugins/hve-core/README.md)

Research, plans and reviews are written to `.copilot-tracking/` in your project. The folder name is
kept from HVE Core so the files stay compatible with teammates who use it in Copilot.

## Optional: GitHub, Azure DevOps and Microsoft 365 (MCP servers)

Ten agents read or write issues, work items, pull requests or Microsoft 365 content through MCP
servers. In Copilot some of these are built in; in Claude Code you add the ones you use. Everything
else, including the RPI workflow, works without them.

```text
/hve-core:mcp-setup
```

It asks which servers to add and adds them to your Claude Code user config. Pass `project` to write a
`.mcp.json` the team can commit instead.

| Server | What it reaches | Sign-in |
| --- | --- | --- |
| `github` | Issues, pull requests, repos | Personal access token in the `GITHUB_PAT` environment variable |
| `ado` | Azure DevOps work items, repos, pipelines | Microsoft account in the browser; needs your organization name |
| `workiq` | Microsoft 365 meetings, email, documents | Work account; your Microsoft 365 admin must enable Work IQ |
| `microsoft-docs` | Microsoft Learn documentation | None |
| `figma` | Figma files (design-thinking export) | Figma account in the browser |

The server names must match exactly, because the agents' tool lists use them. Tokens never go in
`.mcp.json` or the chat: the GitHub entry reads `${GITHUB_PAT}` from your environment. The
`outlook-drafter` agent uses a WorkIQ Mail server that HVE Core doesn't document, so it isn't covered.

## Update

```bash
claude plugin marketplace update hve-core-claude-code
claude plugin update hve-core@hve-core-claude-code
```

Then rerun `/hve-core:setup` in your projects to refresh the rules.

## What is included

| HVE Core (Copilot) | Claude Code |
| --- | --- |
| 82 skills | Skills, run as `/hve-core:<name>` |
| 57 custom agents | Subagents, or a main session with `claude --agent hve-core:<name>` |
| 35 instructions files | Path-scoped rules, installed by `/hve-core:setup` |
| MCP server configuration | Optional, added by `/hve-core:mcp-setup` |

Not included: HVE Core's experimental skills and agents, its Copilot installer, and its VS Code
canvases and extension.

## Limits

- Agents that use GitHub, Azure DevOps or WorkIQ can't do those steps until you add the servers
  (see above).
- A few skills mention Copilot-only features such as canvases. A compatibility rule tells Claude how
  to map or skip them.
- HVE Core changes often and calls itself patterns, not a stable dependency.

## For maintainers

Everything under `plugins/hve-core/` is generated by `convert.py`. Don't edit it by hand.

```bash
python3 convert.py build --ref main      # or a commit SHA; needs Python 3.9+ and git
claude plugin validate ./plugins/hve-core
git add -A && git commit && git push
```

The build prints a report of everything it skipped, dropped or could not map; read it before pushing.
The plugin version is the upstream version, the upstream commit and the converter revision (for
example `3.2.2+0e5623a.2`). Claude Code only delivers an update when the version changes, so bump
`CONVERTER_REVISION` in `convert.py` whenever you change the converter's output. Add `--include-experimental` to convert the experimental pieces too. Release
tags up to `hve-core-v3.3.101` use an older layout the converter doesn't read.

| Copilot agent setting | Converted to |
| --- | --- |
| `name: RPI Agent` | `name: rpi-agent`; the description starts with "HVE Core 'RPI Agent' agent" |
| `read`, `search`, `edit`, `execute`, `web`, `agent`, `skill`, `ask_user`, `todo` | Read; Grep, Glob; Edit, Write, NotebookEdit; Bash; WebFetch, WebSearch; Agent; Skill; AskUserQuestion; task tools |
| `github/<tool>`, `ado/<tool>`, `workiq/<tool>` | `mcp__github__<tool>` and so on |
| `model: Claude Haiku … (copilot)` | `model: haiku`; GPT models are dropped so the agent uses the session model |
| `reasoning-effort` | `effort` |
| `disable-model-invocation: true` | Noted in the description: run only when asked |
